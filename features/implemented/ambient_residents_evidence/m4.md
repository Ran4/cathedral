# M4 — Full-population and visual acceptance

## Performance correction before acceptance

The first run was stopped after 3,870 simulation seconds and retained as
`exploratory_m4_1000.log` / `.err`. It is not final acceptance. Source review
identified a full-world publication on every resident phase/claim transition:
one person's local arrival could clone every character's appearance, inventory,
and public state. Resident transitions now use typed `EngineMessage::ResidentStates`
updates. Initial/despawn state remains in complete snapshots; a complete snapshot
supersedes pending deltas. The projected status updates existing actors in place
without changing the mirror revision or body pose.

The sparse seam covers phase, occupied/destination claim, optional ownership,
movement cause, actual roof exposure, and renewed dwell. Counting down an
unchanged dwell does not publish another update. The authoritative status remains
current for prompts and the live debug sheet. Tests cover phase changes without
displacement, cause changes with an unchanged interrupted phase, countdown,
renewal, existing inventory/pose preservation, and removed actor handling.

Two isolated matching 600-second runs at 1,000 extras preserve **identical
motion/needs/distribution census records** in all 21 samples. Pump/report time
fell from **68.790 s / 5.733 ms per poll** to **54.675 s / 4.556 ms per poll**,
a 20.52% reduction. The latter published 220 full snapshots and 12,717 sparse
actor updates in 12,000 polls. Commands use the formal flags below with
`--watch-clock 0.16666666666666666`. Exact hashes and values are in
[`m4_pump_comparison.json`](m4_pump_comparison.json); both raw traces remain.
This comparison isolates the notification change on the same final geometry;
it does not claim that all remaining frame work became cheaper than M0.

## Formal measurement procedure

After full simulation/backend/app tests and current executable builds:

```sh
UV_CACHE_DIR=/tmp/cathedral-uv-cache uv run --no-project \
  features/implemented/ambient_residents_evidence/run_final.py
```

The helper runs 1,000 then 2,000 extras, serially and without competing
builds, benchmarks or GPU work, using:

```sh
target/debug/cathedral-headless --fake --stage --curiosity --night-office \
  --weather clear --extra-ambient 1000 --start-day 2 --start-office dayspring \
  --seconds-per-day 3600 --watch-clock 2 --trace-motion --census-per-day 120
```

`--trace-motion` preserves 0.05-second movement/needs/calendar polls at normal
1×. Each full run has 144,000 polls and 241 census observations. The initial
reference is excluded from sampled motion means; all 240 subsequent samples,
including the final floating-point endpoint, are retained. The denominator is
the full `InCity` generated population, including all outdoor resting proxies.
There is no authoritative indoors count. Actual before/after poll positions
classify motion; routes, speed and `at_post` do not substitute for displacement.

`summarize_final.py` writes new final JSON/JSONL files and compares the matching
first-day settled daytime subset with the preserved M0 baseline. Settled means
elapsed ≥300 seconds in Dayspring, High Wick or Waning. The full two-day subset
also includes the following day's corresponding offices. Measurements are sparse
30-second observations of a real 0.05-second slice, not integrated walking time.

Pump/report timing includes `Engine::poll`, resulting typed messages and their
headless reporting/drop costs, including cognition requests, movement, round,
needs, snapshot/status publication, ordinary economic/weather/knowledge work and
the authored cast. It excludes asset/generation startup, completion collection,
the separately sampled before-position and census serialization work, and the
final state dump. It is per poll CPU wall time, not a GPU frame-rate promise.

The same helper ends with a 20,000-request capacity/performance observation over
120 normal simulation seconds (`--watch-clock 0.03333333333333333`). This is a
bounded stress interval, not two-day acceptance or a promise to place 20,000.

tmux session. It forces `CATHEDRAL_HEADLESS=1`, removes the audio override, sets
fake cognition, 1280×720 logical resolution, asset root, X11, performance recording
and the requested population. It rejects CPU rendering/missing assets, watches
the launched PID's windows for `IsUnMapped` and no focus, and owns a process-group
watchdog. It never touches the developer's tmux sessions. Microphone input is
disabled with the existing V toggle before the engine handshake.
