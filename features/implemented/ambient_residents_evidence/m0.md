## Reproduce the baseline

Build with `cargo build -p cathedral-backends --bin cathedral-headless`.
The dev profile has opt-level 1; dependencies have opt-level 3. Exact Rust
version, binary/data hashes and the starting git HEAD are in
[`baseline_meta.json`](baseline_meta.json). Run the populations serially with
no other benchmark/build running:

```sh
target/debug/cathedral-headless --fake --stage --curiosity --night-office \
  --weather clear --extra-ambient 1000 --start-day 2 --start-office dayspring \
  --seconds-per-day 3600 --watch-clock 1 --trace-motion --census-per-day 120 \
  > /tmp/ambient-1000.log 2> /tmp/ambient-1000.err
# Repeat with --extra-ambient 2000.
UV_CACHE_DIR=/tmp/cathedral-uv-cache uv run --no-project \
  features/implemented/ambient_residents_evidence/summarize.py /tmp/ambient-1000.log
```

M0 captures one complete game day at each population, including meal, evening,
night, and morning transitions. M4 must run the specified **two** days and
compare its first day with this baseline. `--night-office` preserves the
existing ambient evening roll; weather is forced clear to isolate ordinary
behaviour. Stage, novelty and curiosity gates match the shipped configuration;
the player stays at the shipped initial position. Cognition is deterministic
and fake. No `T` key or time-scale command is used.

The existing `--watch-clock` driver can advance by 18 seconds per poll at
3600 seconds/day; `--census-by-area`/`--trace-food` cap that at 3 seconds.
Neither preserves walking: the mover realizes at most 8 × 0.05 = 0.4 seconds
per poll and drops the rest. The new opt-in `--trace-motion` driver uses
**0.05-second polls**, preserving the movement/needs/calendar relationship.
This does not change the game's debug acceleration behaviour or the existing
driver when motion tracing is off.

## What the diagnostic measures

`round/motion.rs` owns pure, host-requested observations. `Engine::motion_positions`
captures positions **and controlling causes before the measured poll**;
`Engine::motion_census` compares them afterward. This ordering matters:
movement runs before the ladder, which can finish or replace a route in that
same poll. Rotation, stale speed and a pending path alone do not count as
walking. A custody follower can move without having its own path.

`Townsperson::motion_cause` is a small observation-only route-commitment tag.
The ladder never reads it. Existing well/food/market/intent/custody ownership
supplies their causes. `walking_by_cause` retains the detailed breakdown;
the disjoint top-level buckets are stationary, optional (wander/legless
recall), domestic, explicit intent, emergency/custody, routine/needs, and
unclassified. Homeward scheduled trips and household water returns are
domestic; ordinary work commutes remain round traffic, not optional resident
walks. A work-post recall is currently included in `round`, not distinguished
from the initial commute. This milestone does not claim to quantify that
particular feedback loop separately.

Generated and authored populations are separate, keyed by `LoreProfile.generated`,
and exclude the player. The full `InCity` population is the denominator.
`indoors: null` is intentional: this repository has no indoors state.
`resting_at_home_proxy` means stationary within the existing home arrival
radius; it remains in `present`. Actual source/stall queue vectors supply
queue membership, with named queues reported separately. Hunger, housing,
occupation and leg counts support later policy comparisons.

There are no resident patches yet. `occupied_cells` uses stable **20 m XZ
observation cells**, explicitly identified as a baseline spatial proxy, not
validated patches or reservations. The probe also tracks membership in the
initial cell and distance beyond 15 m from the initial position. Time away is
rectangle-rule integration at the reported 30-second census cadence, including
the longest sampled episode. It is an estimate of location over time, not a
claim about travel distance or walking between the sparse samples. M1/M2
should extend this seam with real patch/spot state while preserving these
comparable spatial observations.

The baseline binary's final time clamp exposed a floating-point boundary bug:
3600.000000004 was clipped to 3600.0, suppressing the last 0.05-second movement
slice and falsely reporting everyone stationary in the terminal sample. The
final driver removes that clamp. Original observations are retained; the
extractor marks that endpoint `motion_sample_valid: false` and excludes it
from motion summaries. All other samples are retained. The endpoint remains
useful for position/queue/needs counts. This omission is explicit in each
summary's `excluded_motion_samples`. The normal driver does not clip its
increments after the correction.

Motion/queue/hunger means in the table use the settled daytime subset; cell
endpoints, time away and pump costs use the full run. Explicit-intent,
emergency/custody and unclassified **generated** walking are zero in this
clear, unprovoked scenario. Authored actors are retained separately in each
raw sample. The mean population at the home-resting proxy during daytime is
24.3 / 46.9, included above. The loss of occupied cells is spatial migration,
not despawning: every sample retains all requested generated actors.

In valid daytime samples the actual walking count differs from positive
movement speed by at most **4 / 6 actors**, accounted for by arrivals and
same-poll state changes. The final driver was also exercised through an
above-boundary 13.00000000000005-second endpoint: **844 actual walkers and
844 positive speeds**, rather than an artificial all-stationary observation.
The command and final binary hash are in
[`endpoint_regression.json`](endpoint_regression.json). This check ran after
the final headless-driver tests passed again.

## Spatial and visual probes

[`probe_fixtures.json`](probe_fixtures.json) pins current city coordinates,
ground/elevated cameras, node/door identities and edge-width observations for
the Wickmarket, Tenterhook Lane, Burnt Court and the Needle. Ground-camera XZ
points were checked against the current walkable bitset. It is a deterministic
framing plan; M4 must verify the framing and retain any adjustments in this
file. Never scale these already-current coordinates by 0.7.

M4's repeated views should include 30, 180 and 600 seconds plus evening views,
with identical clocks, requested populations and cameras. Add debug views
showing the final resident routine/reason/patch/spot once those exist. A camera
move does not reset or repopulate the simulation. Fixture bounds are observation
regions, not permission to stand in door approaches or choke routes.

`bevy_perf.py` is the prepared driver for short serial hidden-window Wickmarket frame baselines
with the pre-feature compiled Bevy binary, its exact hash, requested logical
1280×720 resolution, normal clock and clear weather. It samples X11 mapping
and focus for the process's own window throughout. The script removes the
audio override and always sets `CATHEDRAL_HEADLESS=1`. Perf summaries preserve
the existing steady-after-60-seconds convention and requests repeated clean
ground views plus an elevated view. No valid GPU frame/visual baseline was
obtained in M0: Bevy selected **llvmpipe CPU Vulkan**, and `nvidia-smi` could
not communicate with NVIDIA even in an unsandboxed read-only check. With
assets loaded, session 803 timed out after 120 wall seconds before completing
the planned 30-second game-time view. See
[`frame_baseline_unavailable.txt`](frame_baseline_unavailable.txt).

These attempts are **excluded** from acceptance and GPU performance claims.
The initial trial's mapping proof remains in
`excluded_session801_window_checks.json` (180 checks, always unmapped and
never focused); its frame output is explicitly named
`excluded_session801_frames.json`. The driver now rejects a CPU adapter early.
M4 must obtain real-GPU frame and visual evidence; M0's deterministic camera
plan is geometry-checked but its valid rendered framing remains unverified.

When launching the binary directly, **set `BEVY_ASSET_ROOT` to the repository
root**, as the script does. Without it Bevy searches `target/debug/assets`;
the initial trial (session 801, and interrupted session 802) had missing
materials/fonts and is excluded from visual and frame-cost evidence. Do not
use its numbers or screenshots. Session 803 fixed asset lookup but exposed
the unavailable-GPU limitation above.

### Parent follow-up: GPU access recovered

The limitation above applies to the exec tool's device namespace. A new,
detached session on the existing host tmux server can access the RTX 4070.
The parent reran the unchanged `bevy_perf.py` with:

```sh
tmux new-session -d -s cathedral-ambient-baseline \
  -c /home/ran/src/rust/cathedralbevy \
  'UV_CACHE_DIR=/tmp/cathedral-uv-cache uv run --no-project features/implemented/ambient_residents_evidence/bevy_perf.py > /tmp/cathedral-ambient-baseline-driver.log 2>&1'
```

That detached session exited when the driver completed. It did not select,
split, or otherwise alter a user tmux window. Valid NVIDIA captures now exist:

- 1,000 extras: `logs/session_804_2026-09-06_16_24_45`, 178 mapping/focus
  observations, all unmapped and unfocused.
- 2,000 extras: `logs/session_805_2026-09-06_16_26_20`, 180 observations,
  all unmapped and unfocused.

Both selected NVIDIA GeForce RTX 4070, driver 535.309.01, Vulkan, and loaded
the repository assets correctly. `baseline_1000_frames.json`,
`baseline_2000_frames.json`, and the matching `*_window_checks.json` describe
these runs; earlier excluded trials remain excluded. The elevated Wickmarket
camera has now been visually checked against the rendered scene.

**Timing caveat:** these hidden runs paced at almost exactly 1 frame/second,
while individual GPU stages took milliseconds. Their wall-frame percentile
is therefore not evidence of ordinary game performance or crowd CPU cost.
Drive `sleep` uses `Time<Real>`; with long-frame clamping, 30 wall seconds
are not 30 simulation seconds. The screenshot names describe drive waits,
not verified simulation ages. M4 must use actual simulation age when checking
persistent behaviour. A separate launch investigation is in progress; the
normal-speed pure-sim measurements above are unaffected.
