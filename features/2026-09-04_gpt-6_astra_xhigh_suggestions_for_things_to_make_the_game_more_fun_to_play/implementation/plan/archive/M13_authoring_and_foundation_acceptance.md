# M13 — Authoring tools and reusable-system gate

Prove that the foundations can host another investigation before creating the real case. This is the user's systems-first requirement made testable.

## Entry

M0–M12 are accepted, including whole-world persistence. The shared knowledge feature has shipped end to end. No real-case engine branches are necessary for the development scenarios.

## Content packs

Finalise the versioned namespace and manifest whose identity begins in M2 and whose typed module declarations/loaders ship incrementally in M4–M12. M13 composes those sections, closes cross-module validation and supplies authoring tools; it is not a late rewrite that first makes earlier systems data-authorable. Packs bind existing cast roles and stable places/portals, install authored history at world creation, define physical documents/objects, provide statement/strategy content, compose activities and specify evidence rules and available outcomes.

Use closed typed declarations with source locations for diagnostics. Reject dangling IDs, invalid role capabilities, cyclic containment, inconsistent dates, inaccessible essential locations, impossible resource requirements and unsupported rule predicates before starting the world.

Keep private author truth separate from player-facing text and actor-specific knowledge. Validate that each seed holder and historical witness is intentional. A debug view can inspect everything; normal prompts and notebook projections cannot.

## Tooling

Provide documented developer commands to create a fresh fixture world, select an initial position/time, inspect an operation/order's state, print its last transition/reason, validate a pack and export a replayable evidence trace. Exact CLI/drive spellings are defined when implemented; do not document nonexistent flags as already runnable commands.

A developer shortcut starts the same production content and services with deterministic setup. It must be explicit that it creates/resets a development world. Ordinary saves never receive an invisible pile of clues or a retroactively rewritten incident.

Create a content-author guide with one complete small example, schema/reference documentation, a checklist for knowledge/provenance, an example activity, an evidence rule with an alternative and a missed-appointment continuation.

## Required independent scenarios

| Scenario | What it proves |
|---|---|
| Misattributed workshop loss | Witnesses can clear someone without identifying a culprit; repeated hearsay stays correlated |
| Disputed collection | A document and physical examination support a property finding; consent, missing original and an admission create different continuations |
| Institutional pursuit exercise | An order for a different citizen is delivered and executed off stage; changed leads, recall and custody persist |
| Agreement and service exercise | A payment/confidential undertaking and a one-use cargo/service favour reserve real resources, fulfil or default and survive interruption |

These can be compact development content, but each must be playable through the normal interface and headless services. They should not merely reskin the final case's sixteen clues. At least one has no offender and one has a different evidence structure and order of discovery.

With the player elsewhere and cognition unavailable, an informed NPC must lodge their own supported account, an uninformed NPC must contribute nothing, and the scheduled reviewer must decide from the actual lodged bundle. A learned warning changes an actor's permitted activity strategy without a case-ID branch. Prove private-detail contamination, provisional sponsorship and scoped order-backed entry in these independent fixtures too.

## Gate demonstration

An author adds or changes a small investigation using data and the documented capabilities. No new branch in `actions.rs`, `round.rs`, the finding evaluator or guard service may inspect its pack ID, actor name or quest stage to make it function.

Run every scenario with typed/explicit controls, a fake backend, unavailable cognition, and a live provider for flexible conversation. Mechanical correctness must be the same. Repeat with player absence and save/load during its important transitions.

The present minimal fake dialogue and short silent fake audio are insufficient for asynchronous failure or language acceptance. Supply controlled delayed/reordered/error completions and explicit semantic inputs separately. Each Vxx evidence record identifies fixture/input, source/content/geometry/behavior versions, time policy and actual result as described in [RUNTIME_BUDGETS](RUNTIME_BUDGETS.md).

Recheck complete persistence: new observations, portals, grants, object locations, activities, statements, submissions, findings, orders, assignments and dispositions all restore. A successful M3 before these systems existed is not enough.

## Acceptance

- Packs fail with actionable source diagnostics before partially seeding a world.
- Distinct scenarios use the same runtime services and differ in authored data.
- A player can understand the action/result flow without reading the schema.
- All scenarios remain coherent under missed appointments, interrupted operations and unavailable participants.
- The ordinary city continues while every interface is open.
- No correctness-critical step waits for an idle LLM turn near the player.
- Saves resume every system introduced through M12.
- The cost profile remains bounded and measured against M0.

Hand over the actual schema, API reference, authoring guide, test evidence, debug commands and known limitations. Reconcile the GDD content against those shipped capabilities once, rather than writing a case against each interim prototype.
