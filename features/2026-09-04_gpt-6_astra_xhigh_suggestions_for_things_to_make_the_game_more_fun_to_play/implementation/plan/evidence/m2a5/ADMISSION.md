# M2a5 bounded admission — 2026-09-08

Existing encoded/expanded component ceilings remain 128 MiB, JSON depth 64 and shared retained cohorts 1 GiB. The new components expose Serialize for explicit wire DTOs but no public Deserialize bypass. Export visits borrowed state and admits its full measured peak before cloning/extracting private owners. Decode admits the raw input and nonallocating lexical preflight before any typed records. No public partial World/Engine replacement is provided.

## Attached record and raw-input charges

The unchanged meter charges 512 B per object/array, 64 B per key/scalar/string and 2 B per encoded string byte. Every KnowledgeCost reports `peak_bytes = 4096 + 4*expanded_upper_bytes + 3*encoded_bytes + validation_working_bytes`, where `validation_working_bytes=4,456,448`. It combines 256 KiB with a separately justified 4 MiB installed-definition allowance. The complete combined allowance is charged before context validation/extraction and before typed decode, even for an empty component. All charges follow the Admitted bytes/DTO/opaque candidate until drop; candidate conversion never reduces a raw-input charge to its smaller canonical encoding. The public 1 MiB-padding regression retains the extra 3 MiB before and after conversion, and refusal tests observe released reservations.

The three encoded copies cover retained input plus up to doubled escaped-string scratch; bounded Text visitors run after serde escape decoding. The four expanded copies cover simultaneous typed Wire Vecs, private map/index reconstruction, DTO/candidate validation and transient record/error storage. Export explicitly deep-copies both Arc holdings and air so the saved payload does not rely on sharing a later-mutating Running store. Encode writes into a counted, preallocated buffer and disposes its consumed DTO; a conservative peak lease stays attached to the bytes. Public read-only candidate inspection does not expose a production adoption seam.

This is a closed shape proof, not permission to deserialize arbitrary generic types. Records are externally tagged or explicitly field-tagged adapters, with mandatory nullable fields and no seed-loader defaults. Every declared FactSource payload is private to its owner adapter; malformed source variant/type/field failures become a generic sealed-provenance error. Runtime FactSource still has no Serialize/Deserialize/Display/Default and redacted Debug. Recursive unknown/many-empty payload tests assert the actual nesting/expanded preflight refusal before ordinary unknown-field validation can hide admission removal. Real said-field escaped/multibyte tests exercise the 65,536 UTF-8-byte text limit.

Target layouts from the ignored diagnostic: Fact/FactV1=272 B; Holding=88; FactView=32; Drift=40; Occasion=64; LearnedHow=104; Knowledge=280; KnowledgeWire=328; HoldingRow/AirRow=48; KnowledgeDto=480; WorldKnowledgeDto=504; EngineKnowledgeDto/Wire/candidate=1080; EngineMessage=232; JournalEntry=104; WardHeatRow=56. The 1080 B Engine descriptor is supported by the enclosing object and its many mandatory key/scalar/container charges, rather than an invented 1024 B universal struct ceiling. These target/build assumptions remain part of M2a1's exact compatibility policy.

Map rows pay their own field/record charges as well as the parent map and key charges. A sparse singleton Fact BTree root must reserve all 11 slots: `11*(272+4)+168=3,204 B`; the minimal fact's lexical charge exceeds this (asserted by the focused test). Holder maps' ActorId (24 B) + Vec (24 B) slots cost `11*48+168=696 B`, covered by their actor/rows object and first key/container even before Holding rows. Occasion maps cost `11*(24+64)+168=1136 B`, covered by their record plus parent container and first key charge. Simple scalar maps similarly require the parent container **plus** first key/value charges, not 512 B alone. Nonroot nodes have at least 5 live keys, so ordinary occupied nodes need less per record than these sparse witnesses. Growable Holding Vecs cost at most 2*88 B per retained row, well below each explicit row's object/fields/view charges; air, receipt, journal and dedupe rows receive analogous array/object/scalar charges. Arrays preserve sequence; actual set/map duplicates are rejected rather than silently overwritten.

## Geography and uncached centroid work

The supported context policy admits at most 512 ordered areas and 4,096 total boxes, with scalar-valid IDs, finite point coordinates within the existing 1e6 point policy, and per-text bounds. AreaMap's own schema/axis/ID/geometry checks then run under admission. Its overlap pass is bounded by 4096*4095/2 comparisons. Fact catalogs have an independent 4,096-spec context limit, rather than the 256-live-fact cap; every context family additionally streams at most 4 MiB into SHA-256. Salience values are checked finite before hashing, and household-door keys/counts/points are checked before nonfinite JSON could collapse to null. Borrowed installed storage belongs to the supplied Running/backbone candidate and is not falsely included as newly owned payload.

AreaMap validation simultaneously retains a BTreeSet<&str> and Vec<(&Area,usize,&AreaBox)>. Measured tuple size is 24 B and borrowed string key 16 B. At 512 IDs, the conservative 103-node bound costs `103*(11*16+168)=35,432 B`. Even a doubled 4096-box capacity costs `8192*24=196,608 B`; combined 232,040 B leaves room under 256 KiB for bounded traversal/errors. The actual installed map has 71 areas.

Adjacency reconstruction starts after that geometry pass is destroyed. It preserves the exact ordinary distance/ID ordering and distinguishes default uninitialized adjacency from an initialized map. **256 KiB is not claimed as an independent adjacency bound.** `nearest_areas` truncates without shrinking, and an implementation of Vec collection could retain that original allocation in each AreaKey row. Charge all 512 outer rows for a complete 512-entry, 16 B NearestArea query: 4,194,304 B, plus 512*24 outer headers, two 512*16 active-query/sort buffers and 4096 miscellaneous bytes, totaling 4,227,072 B. This fits the combined 4,456,448 B. The target diagnostic actually reports 512 rows, maximum row capacity 8 and 20,480 B retained; the proof uses the larger source-derived possibility.

Cached WardHeat coordinates are immutable compiled-home centroids. The validator calls pure `crowd::ward_map`, preserving `homes::ward_marks`' raw-district/x/z ordering, then sums/divides in exactly the ordinary centroid initializer's order and checks f64 bits. It never calls the ward-grid or centroid singleton initializer. Before parsing, it inspects the exact compiled Homes input: 134,878 encoded/1,118,084 expanded. The inherited closed HomesDoc/HomeEntry/BedlessEntry layouts are 96/64/24 B; `2*1,118,084 +3*134,878 +131,072 =2,771,874 B <=4,194,304 B`. The 128 KiB remainder covers mark Vec growth/stable-sort scratch and 8 ward accumulation/result BTree nodes. This reuses M2a3's admitted Homes parser shape. Adjacency reconstruction and home parsing have sequential lifetimes; the single combined allowance remains attached throughout and after candidate conversion. A cold-helper/ordinary-singleton equality witness and altered-centroid corruption test pin this contract.

## Counts, policy domains and diagnostic limits

Per-owner gates include 256 live facts, 6 stored holdings/name, 24 air rows/ward, 64 player receipts, 64 distinct receipt mouths plus one unattributed telling, 3 seated keys and 2,048 stage-telling pairs. Names/occasions/raises/door timers have a 25,000-row supported-format cap; the aggregate ceiling still limits their combined Cartesian occupancy. This is not a promise that every runtime population can simultaneously fill every independent cap under 128 MiB. Text is 65,536 UTF-8 bytes; general actor/item/fact IDs retain the actual 64-Unicode-scalar validity rule without truncation.

Sparse allocation handles remain exact. V1 reserves 257 further FactKey/sequence allocations by rejecting next_key beyond u32::MAX - 257 or next_sequence outside 0..=i64::MAX - 257. This is supported-save headroom for one live-store turnover, not a proof of indefinite lifetime or the complete next-poll mint horizon. Stir/revision wrap and historical names/receipts remain legal; no monotonic relation is invented. Logical and signed-calendar anchors reuse M2a1's declared sentinel types; only actual Never owner sentinels map to Never. Global effective clock-rate, accounting and catch-up CPU horizons remain complete-envelope gates.

`alibi_knowledge_cost --mode authored|populated --samples N --output PATH` reports the six unchanged phase arrays. Preflight includes borrowed lexical costing and binding; export includes admission, deep extraction, context/owner validation; encode counts/writes/disposes DTO; decode includes raw preflight, typed private maps and validation; candidate validation repeats pure validation and moves the candidate, not construction of a World; drop covers the retained save bytes and candidate. It deliberately resets only the diagnostic knowledge store, mints 6 current templates via production writers, learns 6 holdings for every actual actor, warms 8 wards, preserves one invalidated historical receipt/seated key/offered occasion and runs ordinary setup polls for journal/ward caches. Its templates include place/day tokens; actual +2,000 citizens use production placement. This measures one explicit active scenario, not every legal knowledge/city state or universal p99.
