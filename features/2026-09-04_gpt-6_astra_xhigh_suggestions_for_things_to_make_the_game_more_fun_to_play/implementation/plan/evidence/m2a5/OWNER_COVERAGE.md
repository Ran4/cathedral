## Reference and projection distinctions

`Knowledge::learn`, occasion and raise writers accept bounded actor names without a current World existence check. Those name-keyed records, frozen own/seeded/quiet names, receipt mouths and sealed provenance are historical/attempted knowledge rather than exclusive resource holders. Live Holding/Air keys resolve to the current fact store; player receipts and seated keys deliberately survive invalidation. The next ordinary source check determines whether a stale custody/item/quest reference is still true. Candidate validation does not publish or sanitize it.

Journal text/attribution/standing is cadence-owned observable state and can legitimately lag current facts. Ward centroid/label identity is immutable installed projection context and is checked exactly. The host's future initial UI republish policy must be separate from these Engine publication cursors and from simulation receipt accounting.

The global WardGrid is a pure immutable accelerator of compiled homes and constants; cache warmth is not authority. Original input/formula compatibility is bound here and behavior/build/target compatibility remains M2a1's mandatory manifest policy. Area adjacency dense keys depend on exact installed area ordering; generated residents' geography and all other resolver bindings still need whole-owner composition.
