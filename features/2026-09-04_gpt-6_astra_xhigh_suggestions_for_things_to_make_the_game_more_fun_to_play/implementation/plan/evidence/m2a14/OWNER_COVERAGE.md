# M2a14 accepted cognition inputs — 2026-09-09

Status: M2a14 component implemented, verified and independently accepted (2026-09-09); see [coordinator review](coordinator/review.md). Complete M2 and host adoption remain pending.

The additional authority is the exact `Option<u32>` passed to a successful cognition request. The two private flight types own an inline `AcceptedOutputBudget::{MissingLegacy, Accepted(Option<u32>)}`. Scheduler writes it only after `request_with_budget` succeeds; Night resolves once and writes it only after `request_night` succeeds. `Accepted(None)` means an intentional provider-default argument. Missing historical authority is a different variant.

The runtime ownership is deliberately the existing flight's lifetime. Busy, rendering failure and semantic admission deferral create no accepted input. Scheduler's ordinary failure retry keeps its semantic root and existing backoff/lane behavior, and resolves a fresh argument on its next successful submission. Night's Busy front row similarly retains only its original obligation/incarnation, not an attempted budget. Closing a scheduler or disabling Night retains its outstanding flight. Floor/capacity holds retain its original input. Completion, replay/refusal cleanup and stale-incarnation retirement drop the accepted argument with that flight. No independent index can survive a removed flight.

Historical scheduler and Night V1 codecs retain their byte format and scope. Their explicit skipped runtime field defaults to `MissingLegacy`; their export/copy paths also erase the new field. Closed V1 wire rejects attempts to inject the skipped `output_token_budget` field. V1 owner validation remains available, but a legacy-only owner cannot export the new complete input component. Historical fixtures are not rewritten.

`EngineCognitionInputsDtoV1` is a separately admitted sidecar. Its mandatory nullable `scheduler` and `night` rows preserve exact method, original prompt and budget. Scheduler binds actor, incarnation, request, semantic root and original selection lane; Night binds person/ward subject, incarnation, request, semantic root and owed day. None is valid for a row only when that owner has no flight. Null budget inside a present row is an actual accepted argument. Missing row/budget keys fail parsing.

The original prompt is duplicated only in the exported sidecar, up to two 65,536-byte strings. Comparing full strings avoids introducing a hash-collision assumption into exact input binding. Running retains no second prompt. All public row/DTO types are Serialize-only; private closed decoders enforce mandatory options, strict string method/lane/ward tags and the existing bounded identity/text/root adapters. Candidates expose borrowed rows and cannot construct or install a scheduler, Night owner or Engine.

Live validation borrows one Engine and checks both existing owners against its ledger and body. Saved validation borrows unadopted scheduler/Night candidates and creates their contexts from one backbone, ledger and boundary with the supplied saved clock. It validates scheduler then Night sequentially and explicitly compares all component boundary bits, including nested Night/world records. No temporary World/ledger, constructor, prompt rendering, cleanup, ordinary poll, external service or retry runs during context construction/export/decode/candidate validation.

The sidecar supplies an explicit saved budget where the matching legacy component has `MissingLegacy`. A live known budget must additionally compare equal. All other row fields always compare exactly to the borrowed flight; current significance/lore/presence never reconstructs the input. This is component agreement, not a complete compatibility manifest, protected-root inventory or proof of an untrusted author's claimed historical provider input.

Complete M2c execution replacement and once-only retry/adoption remain pending. Held success/error still belongs to the existing component and requires no new provider call. Complete Engine/World/host assembly, initial readable publication, all-consumer horizons and Running/Save/Load/retiring lifetimes remain mandatory. No complete-save or synchronous-host-frame claim follows from this cut.
