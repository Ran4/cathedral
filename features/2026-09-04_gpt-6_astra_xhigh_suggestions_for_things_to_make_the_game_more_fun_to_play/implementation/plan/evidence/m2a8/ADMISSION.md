# M2a8 animals admission and closed layout — 2026-09-08

Status: Implemented component bound; final layout passed, coordinator verification pending. The global 1 GiB, 128 MiB encoded/expanded and depth 64 limits are unchanged.

The existing nonallocating lexical preflight counts the complete borrowed component before extraction or typed parsing. For expanded charge E and original input J, each attached cohort retains at least `4,096 + 4 × E + 3 × J + 1,048,576` bytes. Every object/array charges 512 B, every key/scalar/string 64 B and every encoded string byte two more. Original padding and escape charges survive candidate conversion; canonical re-encoding cannot shrink a received lease. Failed shape/reference/numeric validation and disposal release the entire reservation. Save bytes and a Load candidate each retain their lease independently.

The extra 1 MiB allowance covers bounded borrowed-ID validation and fixed context/serializer/error work. World or unadopted backbone context checks logical time and the 25,000 character count before any ID index allocation. Both nav bindings copy only 32-byte immutable fingerprints; NavData can only be constructed by its validating parser. No graph, registry, resident geometry or pathfinding cache is copied, reparsed, rebuilt or warmed. Existing actor-map lookup allocates nothing. Exact nav-none/some and the Engine's independent config.nav binding remain mandatory nullable records.

## Closed collections and validation scratch

Dog identity validation first checks at most 25,000 rows and every bounded identity/prose/path/numeric field. Only then it collects Vec<&DogId>, sorts it with allocation-free sort_unstable and checks adjacent duplicates. This temporary index does not reorder the pack. An 8-byte pointer is 200,000 B at the maximum count, or less than 400,000 B even under a conservative doubling-capacity bound; its four-slot singleton floor is 32 B. There is no BTree sparse-root allocation. The 1 MiB allowance covers this with more than 633 KiB left for fixed borrowed context and bounded error/serializer state. It is dropped before export clones or before the candidate is moved; the conservative full working allowance nevertheless remains attached.

The final frozen-source layout diagnostic reports Dog 200 B, DogCoat 1 B, Vec3 24 B, DogId 24 B and borrowed ID pointer 8 B; World DTO/candidate 72 B, Engine DTO/candidate 152 B and LogicalTime 8 B. The Dog Vec first four-row allocation is 800 B.

The Dog wire explicitly lists all fourteen fields. Each row contributes one 512 B object, fourteen 64 B keys, eleven direct scalar/string values (704 B), two coordinate arrays (1,024 B), six coordinate scalars (384 B) and its path array (512 B), at least 4,032 B before field-name/text byte charges or path contents. This covers the concrete Dog struct and its Vec's four-row first allocation floor; subsequent capacity remains below twice populated rows. The three owned strings (ID/name/description) are charged by lexical key/scalar/string bytes, with geometric parser escape scratch separately covered by 3 × J. Owner prose is bounded at 65,536 bytes and IDs at the existing 128-scalar/512-byte sufficient guard.

Each waypoint is a 24 B Vec3 represented by a closed exactly-three-finite-coordinate array. It receives 512 + 3 × 64 = 704 B, with a separate 512 B path-array charge. This covers singleton four-element Vec floor, less-than-double growth and the temporary in-progress point. Path limit is 65,536 entries per dog; overall E/J still cap the sum across dogs. The maximum-path test restores exactly that length then refuses one extra; 25,000 is the shape's dog count ceiling, not a claim every such pack fits every aggregate cap. Malformed excess rows/paths are admitted lexically before the typed parser allocates them, then refused by supported-shape validation.

Four E copies conservatively cover explicit DTO/wire/candidate container storage, transient parsing capacity and validation. These are closed owner records, not an arbitrary Deserialize promise. There are no nested map adapters or intermediate DogView collections in the production component path. Remote Dog/DogCoat records fail compilation if their owner shape changes without a reviewed disposition. Unknown and duplicate fields fail; nav is required even when null. The complete Engine has no public Deserialize route around admission.

## Numeric and continuation limits

All stored dog numerics are finite; coordinate magnitude uses the existing city bound. Scalars retain signed/unnormalized values and epoch accepts all u64, including MAX. Empty path with positive speed, pending/resting turn states and arbitrary historical private path Y survive unchanged. No seed-pack, path recomputation, position snapping, rest reroll or wrap headroom restriction runs on capture/load. Finite extremes may still overflow downstream arithmetic under unusual public edits; complete all-consumer temporal/numeric horizons and the supported production input policy remain separate validation gates.

The shared movement_now anchor validates in the existing finite nonnegative logical-time range. It does not impose a universal residual or ordering: no-nav engines leave it unchanged, and historical backward/debug callers can retain it after the supplied boundary. Future production capture must agree with the host's accepted residual and all other movement consumers without lossy subtraction/re-addition.

## Diagnostic phases

alibi_animals_cost uses actual authored 520 actors or production placement of 2,000 extras (2,520 total), the real runtime navigation, and the living authored ten-dog pack. Ordinary Engine polls first publish the resting pack, dedupe a quiet sub-slice, then select a boundary where dogs are concurrently resting, moving and turning with active paths and a fractional movement cadence residual. Ordinary changes witness acceleration and yaw-only turning. No private path/rest/epoch is manufactured for the timed workload. Stop arrival, failed retry, wrapping MAX, signed edits, max path and all corruption cases are deterministic tests outside the small timed pack.

The six arrays are preflight_us, export_us, encode_us, decode_validate_us, candidate_validate_us and drop_us. Preflight counts borrowed full state/bindings; export repeats checks and clones exact authority; encode writes canonical bytes; decode includes raw admission/typed records and validation; candidate validation repeats pure checks and moves the owner; drop releases both leases. Definition lookup and borrowed actor count are independent of cast size except the constant-time actor count and O(log n) player lookup in the existing BTreeMap. These component timings cannot establish whole-envelope or host frame cost.

No cap increases to make complete capture fit. Earlier backbone+Round Save+Load already exceeds 1 GiB excluding Running and other owners. Full phase/lifetime allocation strategy, offload or incremental host-only work, final publication/retirement and full Engine/host composition remain required.
