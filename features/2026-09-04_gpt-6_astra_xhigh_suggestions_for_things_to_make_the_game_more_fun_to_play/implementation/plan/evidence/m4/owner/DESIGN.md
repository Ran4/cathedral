# M4 owner: bounded street-query foundation

This is a first, deliberately street-only slice of M4. It does not complete the milestone or bypass its M3 entry gate. The accepted full checkpoint/adoption, renderer proof, real two-floor building, authored stable portals and movement-faithful stepping prerequisites remain open.

## Source-backed boundary

`NavData` schema 1 is immutable XZ topology at `WALK_Y`; the committed artifact has 10,026 nodes, 10,062 undirected edges and a 2,907 by 3,313 bit grid. The movement layer still flattens elevations. Existing map debug teleport resolves named places and walkable cells but previously did not consult dynamic collision barriers. Dynamic gate collision geometry already has authoritative saved GateRuntime ownership; creating another mutable door/closure resource here would duplicate it.

`nav::query::StreetQuery` borrows the graph and a canonical caller-owned closure slice. A closure is an inclusive XZ rectangle already expanded for the body footprint, with a nonzero stable owner ID. At most 32 are accepted; duplicates, reordered IDs and nonfinite/inverted geometry are refused before search. `Surface::Interior` is an explicit unsupported request, and a street request at another height is refused instead of snapping downstairs.

A route ticket owns an ordinary Route plus the exact graph fingerprint, caller revision and fixed-size closure snapshot. Its checked projection rejects a different graph, revision or closure geometry. This is snapshot identity, not a persistent movement reservation or permission grant. Callers must supply the current authoritative access snapshot at use. No unchecked mutable route projection is exposed. Ordinary route search uses the same A* kernel, heap ordering and costs, with an optional closed-edge predicate. Existing unfiltered API behavior and distance caches remain unchanged. Before search, the supported query envelope is at most 32,768 nodes, 131,072 directed adjacency entries and a combined grid width+height of 16,384 cells. The latter bounds the existing exact-segment scratch, and the adjacency limit bounds route materialization. These are finite component bounds, not admission of the whole running world. A bounded query refuses after 65,536 heap-pop/adjacency-visit work units; there is no fallback to an unchecked route. Closure scanning is bounded by 32 per examined edge.

Graph routes retain legacy snapped-node costs. Exact endpoint approach and current body support remain separate obligations; these routes are not permissive physical-traversal certificates or lower bounds on player travel time. The new explicit segment query uses the existing exact bit-grid segment check plus closure intersection.

## Production consumers

Ordinary `go_to`, chase and seizure budget calculation now requests a bounded street graph route. Its caller deliberately retains the existing XZ nearest-node pricing because World intents are not yet floor-qualified, and supported custody anchors include y=0. The strict point-query API is not imposed on those legacy anchors. An unavailable graph route maps to the existing NoRoute policy; successful route budgets retain the previous length formula. This does not yet teach the NPC mover about host gate closures or adopt floors into World state.

Map click-to-teleport projects active DynamicBarrier geometry intersecting the standing walk band into a fixed stack array. Stone/River gate owner IDs are canonical and derive from the actual collision owner tags. Unowned, duplicate or malformed active barriers refuse. Geometry above/below the walk band is irrelevant. The nav standing radius plus a conservative centimetre is added in XZ; this is a destination guard, not a replacement collision solver. The target chosen by the existing map snapping policy is checked once. A closed destination keeps the map open and emits no teleport; reopening allows the original destination. No silent alternative destination is selected and no new saved authority is introduced. This guard checks the barrier snapshot at input production; it does not add an atomic portal revision to the later TeleportPlayer consumer. Full queued-action revalidation and portal-aware movement remain outside this foundation.

## Verification scope

Pure fixtures exercise detours/reopening, inclusive boundaries, unsupported surfaces, invalid endpoints, duplicate/oversized closures, exhausted work, and stale graph/revision/actual geometry. The committed city graph compares every named-place route from the forecourt with the legacy route, including node/tie/cost equality. Host tests run the actual map click system with real committed NavData and a controlled active gate barrier, without a window, GPU, audio or provider. Existing nav and go_to tests cover compatibility. None of this is full layered spatial acceptance, frame acceptance or an impossibility certificate.
