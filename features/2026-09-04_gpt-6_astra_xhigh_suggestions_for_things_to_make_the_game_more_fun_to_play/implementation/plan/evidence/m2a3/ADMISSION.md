# M2a3 admission argument — 2026-09-08

The existing limits remain: 128 MiB encoded and expanded per component, depth 64, 1 GiB shared cohort ceiling. One attached SavePayload or LoadCandidate lease stays with bytes/DTO/candidate until destruction. There is no complete-envelope admission or synchronous host-frame claim.

## Before allocation

The existing nonallocating JSON meter charges 512 bytes per object/array, 64 per key/scalar/string, and two per encoded string byte. Export counts a borrowed serialization before cloning; decode counts raw bytes before typed serde parsing. Round adds `definition_working_bytes=4,194,304` to `4096 + 4*expanded + 3*encoded`. `decode_with_working` admits this **raw** peak before parsing: whitespace/escapes cannot shrink the charge through canonical reserialization. Input, escape/error scratch, DTO and validation/destruction coexistence are covered. The public DTO has no public Deserialize implementation. Mandatory optional fields, strict map/set adapters and aggregate admission are independent gates.

The runtime accepts only this closed v1 record family, not arbitrary DeserializeOwned shapes. Retained peaks are conservative upper bounds, not allocator/RSS measurements. Four expanded copies cover typed records/collection capacity, validation indexes/projections, serde transient content/error scratch and candidate handoff. Candidate construction moves the decoded BTree maps and validates them; it does not build another seeded Round or World. Encode preallocates the exact counted output; both serialization passes are included in encode timing.

## Concrete layouts and sparse collections

The layout test prints and bounds the target's actual sizes: Round 1,120; Townsperson 296; RoadParty 304; Counter 184; FoodStall 256; WaterSource 152; ResolvedTransformSpec 152; MarketErrand 192; Resident 288; Residents 224; ProjectionAnchor 120 bytes. The Option/enum cases include FoodPhase 32, CounterSession 32, StockSource 32 and ResidentWeather 80. These layout checks belong to this build/target's manifest compatibility, not a cross-platform promise.

Vec growth is at most twice the element count; each structured element pays its own container plus explicit field/key/scalar charges. BTree maps need more than a Vec-size argument: an isolated root may allocate 11 key/value slots even for one record. For the largest Round map value, RoadParty+24-byte key, that is `11*(304+24)+168 = 3,776` bytes with a conservative node header/edge allowance. Townsperson needs 3,688; Resident needs 3,600. Their mandatory fields/containers pay multiple KiB per row; two expanded copies cover even sparse malformed records with null projections, while the other two remain available for validation/serde transients. Ordinary occupied nodes amortize 11 slots across at least five entries. Scalar maps' container plus first key/value scalar charges cover singleton roots: a 24-byte ActorId/String key and u64 value need `11*32+168 = 520` bytes, below `512+64+64 = 640`. Per-key/scalar charges cover ordinary occupied nodes. Owned string payload growth is charged from encoded bytes, including many short/empty values rather than only long prose.

Resident projections are inline in their controller records; only the occupied String owns extra heap, and the ordinary pass reuses that storage. Saved positions and owners are compared directly to geometry/claims. Local shelter validation streams shared candidate iterators against saved ordered rows rather than building an uncharged Cartesian index. Concrete context caps precede those checks: 4,096 patches/25,000 spots/256 shelter slots, 256 shelters/1,024 vertices per polygon, and 256 resolver sites with at most 32 KiB combined site name/ID text. Current baked geometry is 2,682 patches, 9,232 spots and 159 shelter slots.

## Installed-definition scratch

Before parsing trusted embedded definitions, the runtime meters all three installed inputs. Food: 14,716 encoded/213,848 expanded; Rounds: 29,876/398,854; Homes: 134,878/1,118,084. The check is `2*1,730,786 + 3*179,470 + 131,072 = 4,131,054 <= 4,194,304`. Two expanded copies cover the closed authoring records, HashMap/BTree/Vec capacity and temporary recipe/list comparisons. Three encoded copies conservatively cover input plus serde escape/error scratch even though the input is static. The remaining 128 KiB covers the capped resolver's two keys per site, table growth, strings and small source/stall/lamp comparison vectors. A changed asset exceeding this proof is refused before parsing rather than silently raising the allowance.

## Measurements and limits

The `alibi_round_cost` example keeps the historical CLI: `--mode authored|populated --samples N --output PATH`; populated uses exactly +2,000 actually generated citizens. It reports six raw phase arrays, placement, World character count and Round owner counts, encoded/expanded/definition/peak bytes, and shared peak **excluding Running**. Preflight includes borrowed serialization and immutable fingerprints; export includes preflight/clone/all validation; encode includes count+write+DTO disposal; decode includes raw preflight/typed maps/all validation; candidate includes validation of the already constructed indexes and ownership transfer; drop includes both retained payload and candidate destruction.

The first populated diagnostic was 3,510,496 encoded and 51,657,412 expanded bytes; adding definition scratch yields 221,359,536 per cohort, 442,719,072 Save+Load bytes excluding Running. Authored is 1,315,978 encoded/24,203,156 expanded/104,958,958 per cohort. These standalone peaks do not establish coexistence with M2a2: its 813,374,372-byte Save+Load diagnostic plus Round's current retained peaks already exceeds 1 GiB, even before Running. Complete composition needs bounded phased/offloaded work and an explicit charge-lifetime strategy; it may not raise these limits or claim a full save fits by measuring components separately. M2a1/M2a2 historical p99 failures already rule out synchronous host placement. Coordinator release component measurements and matched ordinary-poll comparison remain separate review evidence.
